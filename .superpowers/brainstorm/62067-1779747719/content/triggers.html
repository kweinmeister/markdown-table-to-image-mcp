Conventional OSS CI Triggers

Most open-source projects follow a standard set of triggers to balance safety with developer velocity.

A

The Conventional Approach

Push to main: Runs CI on every merge to ensure the default branch is always stable.

Pull Requests: Runs CI on every PR (and every update) to catch issues before they are merged.

Manual (workflow_dispatch): Allows running CI manually for debugging or custom scenarios.

B

Strict / High-Security

Tags/Releases only: CI only runs when preparing a release. Good for very slow builds, but lacks early feedback.

Scheduled: Runs every night to catch environment drifts or dependency breakage.

C

Minimal / Lean

PRs only: Relies on developers to merge clean code. Saves on CI minutes but risky for branch stability.

Recommendation

For this project, I recommend Option A (Conventional). It provides the best feedback loop for contributors and ensures your main branch stays deployable.
